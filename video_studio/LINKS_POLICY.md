# КАК ОТДАВАТЬ ССЫЛКИ НА ФАЙЛЫ (чтобы не было 404)

## Почему ломалось

Рабочая ветка называется `arena/f4ba045c-repo` — со слэшем. Ссылка вида

```
https://github.com/<владелец>/-/raw/arena/f4ba045c-repo/<путь>
```

отдаёт редирект на `raw.githubusercontent.com/<владелец>/-/arena/f4ba045c-repo/<путь>`,
и там GitHub считает реф только `arena` (первый сегмент) → **404**.

Вторая причина: в корневом `.gitignore` стоит `*.mp4`, поэтому свежие рендеры
не попадали в коммит, и ссылка вела в пустоту даже с правильным рефом.

## Как правильно

1. **Тег или SHA вместо имени ветки.** Ставим тег `delivery_YYYY_MM_DD` на сдаваемый
   коммит (теги и SHA не содержат слэшей, разбор однозначный):

   ```
   git tag -f delivery_2026_11_03 <sha>
   git push -f origin refs/tags/delivery_2026_11_03
   ```

2. **Ссылка «посмотреть/скачать» — blob-страница** (открывается в браузере,
   у видео есть плеер и кнопка «Download raw file»):

   ```
   https://github.com/<владелец>/-/blob/delivery_2026_11_03/<путь>
   ```

3. **Ссылка «прямо файлом» — raw с тегом или с полным `refs/tags`:**

   ```
   https://github.com/<владелец>/-/raw/delivery_2026_11_03/<путь>
   https://github.com/<владелец>/-/raw/refs/tags/delivery_2026_11_03/<путь>
   ```

4. **Не** подставлять в raw имя ветки со слэшем и **не** давать ссылку на файл,
   который не закоммичен.

## Видео и git

`*.mp4` игнорируется, но сданные ролики должны быть в репозитории (в нём уже лежат
все прошлые). В `.gitignore` добавлено исключение `!video_studio/*/v_*.mp4`,
плюс при сдаче проверять:

```
git status --short | grep mp4     # пусто = файл не попал в коммит
git ls-files | grep v_okope       # список реально закоммиченных рендеров
```

## GitHub Releases

Заливка ассетов идёт на `uploads.github.com`, а он в песочнице закрыт
(`HTTP 422 / EOF`), поэтому релизы как хранилище видео не используем —
только теги + blob/raw ссылки.
