## 0. Кто тут главный и как работаем

- **Владелец** — магазин «В ОКОПЕ»: броня, тактика, экипировка, техсредства. Торговля идёт через **Авито**
  (клиенты пишут в чаты) + посты **ВКонтакте**.
- Наша работа: проверить наличие у поставщиков → подобрать/порекомендовать → собрать готовую
  **картинку и текст**, которые владелец пересылает клиенту или выкладывает в ВК одной кнопкой.
- Владелец работает **с планшета** → результат всегда: готовая картинка + копируемый текст.
  Никаких «зайди по ссылке», никаких «запусти команду» в качестве ответа.
- Общение: **русский, прямо, кратко, без воды**. Не знаешь — спрашивай. Не выдумывай НИКОГДА:
  ни цены, ни фото, ни наличие.

## 1. ЖЕЛЕЗНЫЕ ПРАВИЛА (после факапа 22.09.2026 — нарушать НЕЛЬЗЯ)

1. **ФОТО ДЛЯ КАРТОЧЕК И ПОСТОВ — ТОЛЬКО из каталога Димы** (`/getFullImages`) **или от поставщика напрямую.**
   Фото из интернета / маркетплейсов / чужих магазинов — **ЗАПРЕЩЕНО ВСЕГДА**.
2. **Нет фото товара у поставщика** → карточку/пост с фото не собирать. Сказать:
   «в каталоге по нему нет фото — возьми фото у поставщика».
3. **Запрошенного цвета/размера нет** → говорить прямо «НЕТУ». Молчаливая подмена другим
   цветом/размером **ЗАПРЕЩЕНА**.
4. **Цены — только от пользователя.** Нет цены — спроси. Единственное разрешённое исключение:
   розница электростанций = закуп **+10 %** (правило владельца).
5. Порядок работы: **точное наличие + цвет/размер → фото строго из каталога → карточка**.
6. Одна позиция с разными фото = **ОДНА строка** в карточке (список не раздувать).
7. Диск не захламлять: temp-файлы, дубли фото, референсы — удалять сразу после задачи.

## 2. Поставщики

### 2.1 ДИМА — основной (работаем только с ним)

Каталог МойСклад B2B.

| Что | Значение |
|---|---|
| Витрина | https://b2b.moysklad.ru/public/WDuXQTYGsuNZ/catalog |
| API-база | `https://b2b.moysklad.ru/desktop-api/public/WDuXQTYGsuNZ` |
| Товары | `GET /products.json?limit=100&offset=N` (страницы по 100, ~1134 товара) |
| Другие | `GET /categories.json`, `GET /product/{id}` |
| Фото | `PUT /getFullImages` — в теле **полный JSON продукта** (может вернуть `[]` → фото НЕТ) |
| Серверный поиск | `GET /products.json?limit=N&search=<слова>` — фильтрует на стороне МойСклад |

**Поля:** `name, price, stock, code, article, category, categoryId, description, imageURL, id, uom`.

Важно (проверено 07.10.2026 на живом API):
- **Наличие = `stock > 0`.** Поле `available` врёт — всегда `true`.
- Публичная витрина отдаёт **только то, что в наличии** (1134 из 1134 позиций). Распроданое
  из `/products.json` не приходит, поэтому «нет в наличии» = «нет в каталоге вообще».
- **Фото — только `PUT /getFullImages`** с полным JSON товара. Ответ — массив **подписанных ссылок S3**
  (`s3.ru-6.storage.selcloud.ru`), **без расширения файла в URL**, ссылки живут ~60 секунд.
  `POST` и `GET` на этот эндпоинт дают 500 — использовать только `PUT`.
- `imageURL` / `imageURLMiniature` — превьюшки (26×19 и подобные), в карточки не годятся.
- Среди фото поставщика попадается мусор (узкие полоски с размерной сеткой) — фильтруем
  автоматически: `quality: preview|strip` помечается в `catalog/photos/manifest.json`.
- Каталог поставщик обновляет сам → **перед каждым ответом о наличии — свежий снапшот**
  (fetched_at в `catalog/data/catalog_meta.json`; старше суток → обновить).
- Формулировки в ответах клиенту: «**на складе у Димы**» / «**НЕТУ на складе у Димы**».
- Синонимы из практики: «пиксель» = «цифра (ЕМР)» = «цифра/пиксель»; «мох» = «A-Tacs FG Camo / мох».
  А также латиница↔кириллица: клиент пишет «прабос» — в каталоге `PRABOS` (умный поиск это умеет).
- Бюджет из вольной фразы ловится автоматически: «бронежилет в пикселе до 85к» → фильтр «до 85 000 ₽».

## 3. Задачи, которые решаем

### 3.1 Умный поиск и рекомендации по базе
Запрос клиента вольным текстом («бронежилет в пикселе до 85к», «подсумки в мохе») → найти позиции,
проверить живое наличие, показать цвет/размер, предложить замену, если нет. Поддержка:
синонимы (пиксель = цифра ЕМР), опечатки, размеры («52-й» → «р.2 (48–54)»), бюджеты.
Выход: короткий список + вердикт + готовая формулировка для чата.

### 3.2 Карточки для Авито-чата
«Полевой бланк»: фото из каталога, наименование, цвет/размер, кол-во, цена владельца, штамп «В НАЛИЧИИ».

### 3.3 Посты для ВК (второй основной функционал)
Взять снарягу/технику из каталога → написать пост (факты только из описания поставщика) →
приложить фото поставщика → владелец выкладывает. Шаблоны и правила — `docs/VK_STYLE.md`.

**Цены в постах ВК НЕ указываем** (правило владельца, 07.10.2026): ни розницу, ни «цена в личку».
Пост заканчивается призывом написать в личные сообщения.

## 4. Инструменты (этот репозиторий)

| Задача | Команда |

| Электростанции: подбор | `python3 -m catalog.power --pick 12h@62W` |

| Карточка из своего JSON | `python3 media/blank/card.py media/blank/card.json media/blank/out.jpg` |
| Бланк заказа (несколько позиций) | `python3 media/blank/blank.py media/blank/order.json media/blank/out.png` |

штамп «В НАЛИЧИИ» с датой проверки. Логотип берётся из `media/logo.png` (пока нет — рисуется заглушка).

## 5. Примеры выполненных задач (калибровка стиля)

- «Бронежилет в пикселе до 85к, чем полнее комплект тем лучше» → **«ВОЕВОДА 14/23» Стандарт**
  (цифра ЕМР, закуп 79 580) + карточка + допродажа пояса (+3к к закупу) + текст-обзор «что к чему».
- «EcoFlow River 2 Max / River 3 / River 3 Plus, 12 часов на насос 62 Вт» → честно: River-ы не тянут;
  двойной пересчёт с самопотреблением; рекомендация **Delta 3 1500**.
- Подсумки в мохе: одна позиция с разными фото = **ОДНА строка**, 4×1500 = 6 000.
- Позиция без фото в каталоге → «в каталоге нет фото», карточку не собирать.
