```powershell

```

`_assets/` должен лежать рядом с `print-light.html` (пути относительные — от папки `kilowatt/print/`).
Регенерация HTML и копий фото: `python _gen/build_print.py` (использует `catalog/_tools/out/catalog_build.json`).

## 2. Оптимизация веса PDF

Исходные фото товаров — WebP с запасом по разрешению; при прямой вставке PDF весил **10,5 МБ**. В `_assets/` готовятся уменьшенные копии:

- фото строк ведомости — **400 px** по длинной стороне, q80 → `_assets/products/<slug>-400.jpg`;
- фото флагманов и сравнения — **800 px**, q82 → `-800.jpg`;
- обложка/hero — до 1200 px (исходник 802 px, без апскейла), q86 → `_assets/hero.jpg`.

Файлы сплющены на цвет бумаги (`#faf7f0` для товарных ячеек, `#f4f1ea` для обложки), поэтому JPEG без альфа-канала, швов и рамок не видно.

**Почему JPEG, а не WebP.** Проверено: Chrome при печати растеризует WebP в PNG — `preview.pdf` с WebP-копиями получился 5,37 МБ. JPEG встраивается в PDF как есть (DCTDecode): те же размеры и визуально то же качество, но **preview.pdf = 1,89 МБ** (цель ≤5 МБ выполнена с запасом). Качество проверено рендерами: стр. 03 (флагманы, крупные фото 800 px) и стр. 05 (ведомость, 400 px) — без артефактов, кромки изделий чистые; обложка — hero.jpg.

## 3. Что проверено

1. **Формат и страницы:** PDF 11 стр., 209,9×297,0 мм (A4; ширина 209,9 — округление Chrome до 0,1 мм, печати не мешает), `@page size: A4; margin: 0`, каждая страница — фикс. 297 мм с `page-break-after`.
2. **Нет пустых страниц:** ink coverage по страницам 8–25 % (страница 08 — итоги, 6,4 %), пустых/белых листов нет.
3. **Нет обрезки/наложений:** DOM-проверка `qa_print.py` — у всех 11 страниц `scrollHeight == clientHeight` (1123 px при 96 dpi), переполнения 0; визуально просмотрены все 11 рендеров. Исправлены найденные дефекты: невидимые фото ведомости (обнулённые `figure`-margins), наложения в описи документов (вложенные grid-правила), мусорные подписи под сравнением, переполнение ТТХ у кронштейна 500/600/700 (теперь «ПОД КУПОЛ 500/600/700 мм»).
4. **Фото:** 34 позиции с фото — все 43 `<img>` на страницах загружаются (0 битых), 9 позиций — заглушка; пути `_assets/...` и `../catalog/assets/...` резолвятся из `kilowatt/print/`.
5. **QR и телефон:** QR из `catalog/assets/img/qr-phone.svg` на стр. 11 (и в графитовой полосе), телефон +7 (999) 136-71-42 — на стр. 11 дважды и в полосе; проверено текстом и рендером.
6. **Шрифты:** Oswald, Sofia Sans Extra Condensed, Tektur — локальные `@font-face` из `../catalog/assets/fonts/`, кириллица без «тофу» на всех страницах; Unbounded в печати не используется (остался только в исходниках сайта).
7. **Данные:** 43 строки ведомости, суммы по категориям сходятся (14+5+7+2+4+11 = 43; «вне сайта» = 10; с ценой 27 / по запросу 16), цены/ТТХ берутся из `catalog_build.json` без ручных правок.

## 4. Риски и ограничения

1. **Фиксированные страницы + `overflow:hidden`:** при будущих правках текста переполнение будет обрезано молча. После любых изменений — `python _gen/qa_print.py` (проверяет `scrollHeight`) и повторный рендер страниц.
2. **Ширина 209,9 мм вместо 210,0** — особенность округления Chrome при `@page margin:0`; для типографии, требующей строго 210, можно собрать PDF через другой движок или увеличить ширину `@page` на 0,1 мм. На просмотр/печать A4 не влияет.
3. **Фото:** для строк ведомости 400 px при 19 мм ячейки ≈ 535 dpi (с запасом), флагманы 800 px при 72 мм ≈ 280 dpi — на границе для офсета, для цифровой печати достаточно. Обложка: исходник hero 802 px, в схеме изделие занимает небольшую часть — визуально чисто, но для крупной обложки производителя лучше запросить исходник hero в большем разрешении.
4. **Флаги и сравнение** используют одни и те же 800-px копии (визуально идентично, экономит вес).
5. **9 архивных позиций** без фото — так в данных; в макете это оформлено как «ФОТО УТОЧНЯЕТСЯ» + помета «вне сайта».
6. **Цены/наличие** — данные поставщика на ноябрь 2026, ориентир, не публичная оферта; подтверждаются в КП. Юридические формулировки взяты из утверждённых текстов каталога, не переписаны.
7. **Шрифты внедрены как subset'ы вариативных TTF:** в Chrome/Acrobat/просмотрщиках рендерятся корректно; если типография требует текст в кривых — нужна отдельная операция outline (не делалась).
8. **Финальный PDF** следует собирать из `kilowatt/print/print-light.html`, не копируя HTML отдельно от `_assets/`; либо копировать `print-light.html` вместе с `_assets/` в `kilowatt/dist/`.
