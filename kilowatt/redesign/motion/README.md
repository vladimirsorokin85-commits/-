# MOTION KIT — система переходов для каталога «В ОКОПЕ» × НПО «Киловатт»

Набор для светлого варианта каталога (`variant-2.html`, тема `theme-quiet`): появление секций,
hover/focus карточек, sticky-тулбар, плавный скролл и ScrollSpy, модалка товара, корзина-заявка,
переключатель «Вариант 1/2», мобильное меню и полное отключение анимации при
`prefers-reduced-motion`.

Принцип: движение — часть типографики и документа, а не аттракцион. Только `opacity` и `transform`,
длительности 160–420 мс, мягкий `cubic-bezier(.2,.7,.2,1)`, никаких layout shift, неона,
градиентных бликов, параллакса и «выезжающих из-за края» блоков.

## Файлы

| Файл | Что это |
|---|---|
| `motion.css` | все переходы, состояния, keyframes, reduced-motion, печать |
| `motion.js` | IntersectionObserver-появление, sticky, счётчик, модалка, корзина, меню, ScrollSpy, якоря |
| `demo.html` | самостоятельный демо-стенд на реальных секциях/данных каталога + кнопки «показать/сбросить» |
| `shots/` | скриншоты демо: `top-1440.png`, `top-390.png` и состояния (модалка, корзина, drawer, sticky, field-тема) |
| `_build_demo.py`, `_verify_demo.py` | внутренние: пересборка демо из `variant-2.html` и CDP-проверка переходов |

## Подключение (2 строки)

В `variant-2.html` — после `catalog.css` + `theme-quiet.css` и после `app.js`:

```html
<link rel="stylesheet" href="../redesign/motion/motion.css">
<script src="../redesign/motion/motion.js"></script>
```

Итоговый порядок в `head` / в конце `body`:

```html
<link rel="stylesheet" href="assets/css/catalog.css">
<link rel="stylesheet" href="assets/css/theme-quiet.css">
<link rel="stylesheet" href="../redesign/motion/motion.css">   <!-- после тем -->

<script src="assets/js/config.js"></script>
<script src="assets/js/data.js"></script>
<script src="assets/js/app.js"></script>
<script src="../redesign/motion/motion.js"></script>            <!-- после app.js -->
```

Требования: `motion.css` — последним в каскаде, `motion.js` — после `app.js` (нужен уже
отрисованный DOM: карточки, флагманы, сравнение). В `head` скрипт не ставить. Повторно не
подключать. Подключение к `index.html` (вариант 1, `theme-field`) тоже работает: все стили
завязаны на переменные каталога. Если переезжает папка — правится только путь.

Без JS ничего не ломается: все «спрятанные» состояния включаются только классом
`html.motion-js`, который ставит сам скрипт. Статичные секции видны и нажимаются.

## Reduced motion

`prefers-reduced-motion: reduce` (и ручной `html.motion-off` для отладки/демо) полностью отключает
необязательное движение:

* появление секций и сеток — элементы сразу видимы, без `translate` и stagger;
* hover-подъём фото, «Подробнее», подчёркивание — переходы 1 мс;
* модалка, корзина, drawer, burger — без слайд-анимаций (мгновенные состояния);
* счётчик — сразу конечное число, бейдж — без bump;
* smooth-scroll → `auto`; cross-document view transitions отключены;
* «занавес» перехода страницы не анимируется.

Включается автоматически по системной настройке; отдельного класса в разметке не нужно.

## Минимальный список изменений разметки

**Обязательных изменений нет.** `motion.js` сам:

* находит `.topbar`, `.topnav`, `.cat-toolbar`, `[data-count]`, `[data-cart-badge]`,
  `[data-modal]`, `[data-cart]`, `[data-cart-list]`, `[data-overlay]`, `[data-cart-toggle]`,
  `[data-cart-close]`, `[data-add]`, `[data-open]`, `[data-variant-switch]`;
* достраивает мобильное меню (burger + drawer) из `.topnav` — в HTML ничего добавлять не надо;
* выдаёт `article[data-open]` (карточкам и флагманам) `tabindex="0"`, `role="button"` и
  `aria-label` из названия — карточки становятся доступны с клавиатуры;
* ставит `aria-expanded` / `aria-controls` бургеру, `aria-modal` / `aria-labelledby` модалке,
  `role="dialog"` — заявке;
* запоминает и возвращает фокус после модалки/корзины/меню.

Опциональные атрибуты (только если понадобятся новые блоки):

| Атрибут | Что делает |
|---|---|
| `data-motion="off"` | исключает блок/поддерево из появления (например, тех. полоса) |
| `data-motion-reveal` | добавляет одиночный reveal-таргет вне стандартных групп |
| `data-motion-stagger` | дети элемента появляются со stagger 55 мс |

Полезные классы/состояния, которые ставит JS: `html.motion-js`, `.is-in` (revealed),
`.is-stuck` (тулбар), `.is-active` (раздел меню), `.m-locked` (блокировка скролла),
`.m-grid-in`, `.m-cart-new`, `.m-cart-item-in` — вручную их трогать не нужно.

## Публичный API (для отладки/демо)

```js
MotionKit.refresh();        // пересканировать новые блоки (reveal + доступность карточек)
MotionKit.replayReveal();   // проиграть появление заново
MotionKit.openDrawer();     // открыть мобильное меню (в т.ч. на десктопе для демо)
MotionKit.closeDrawer();
MotionKit.closeAll();       // закрыть модалку/корзину/меню
MotionKit.reduced();        // true, если анимации отключены
MotionKit.scrollTo("#catalog");
```

Ручной режим без анимации: `document.documentElement.classList.add("motion-off")`.

## Ограничения и на что обратить внимание

1. **Кнопка «В заявку» в карточке.** В `app.js` обработчик сначала ищет `[data-open]`
   (карточка-контейнер) и открывает модалку, поэтому «В заявку» на карточке сейчас открывает
   товар. Это поведение `app.js`, не motion; в демо добавление идёт из модалки. Если владелец
   `app.js` поменяет порядок (`[data-add]` до `[data-open]`) — добавление с карточки заработает
   напрямую, motion-анимация корзины уже готова.
2. **Корзина и модалка одновременно.** `app.js` может открыть заявку поверх модалки; в
   `motion.css` заявка/оверлей подняты выше модалки (z-index 87/86), иначе она была бы не видна.
3. **Высота шапки.** `motion.js` измеряет реальную высоту `.topbar` (65 px на десктопе, 63 px на
   мобиле) и подставляет её в `--m-topbar`; захардкоженные в `catalog.css` `top: 61/57px` для
   sticky-тулбара заменяются на переменную — якоря и тулбар не уезжают под шапку.
4. **Кросс-документные View Transitions** работают в Chromium 126+; в остальных браузерах
   включается запасной «занавес» (`m-page-veil`). На `file://` браузер может не применить VT —
   это нормально, фолбэк безвреден.
5. **Скриншоты всей страницы.** `--full` снимает секции ниже первого экрана до срабатывания
   IntersectionObserver (они появятся при скролле) — для QA используйте `--sections`.
6. **Демо и прод-пути.** Правка путей к фото в `demo.html` нужна только потому, что демо лежит
   во вложенной папке; в каталоге `app.js` берёт `assets/...` корректно.
7. **Печать.** Все reveal-состояния принудительно видимы, модалка/корзина/меню скрыты — PDF
   каталога не пострадает.
