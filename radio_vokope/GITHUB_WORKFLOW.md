# Регламент работы чата «Радио» через GitHub

Репозиторий: `vladimirsorokin85-commits/-`. Чат «Радио» — один из рабочих чатов команды «В ОКОПЕ»; его зона — эфир, музыка, реклама, брендинг, YouTube-канал @V-okope.

## 1. Базовый цикл

1. **Задача** берётся с общей доски штаба команды или от владельца.
2. **Ветка** от актуального `main`: `radio/<тема>` (например `radio/yt-audit`, `radio/ads-v2`). Если задача продолжает чужую ветку — от неё, с указанием в PR.
3. **Коммиты** малыми шагами, сообщения по-русски, в теле — «что сделано».
4. **Пуш** ветки.
5. **PR в `main`** — «досье сдачи»: что сделано → таблица файлов → где посмотреть/послушать (ссылка по тегу/SHA) → что нужно от владельца → ограничения.
6. **Merge** — после «ок» владельца. `main` не должен отставать: не копить открытые PR месяцами.

## 2. Что куда кладём

| Тип | Куда |
|---|---|
| Код, документы, регламенты, джинглы, небольшие обложки | `main` через PR |
| Музыка/видео от владельца, крупные файлы | ветки-каналы (`radio-inbox` — когда заведём; сейчас `assets-inbox`/`assets-inbox-thermal` по договорённости) |
| Снапшоты данных (треки/плейлисты) | орфанная ветка `radio-data` (аналог `catalog-data`), force-push без истории |
| Секреты | **никуда.** Только локально/на сервере |

## 3. Данные и Actions

- В `main` workflow-файлов нет: они живут в рабочих ветках (`arena/26c1e78e-repo` — `fetch-asset.yml`, `catalog-fetch.yml`, `frontts-fetch.yml`; `arena/f4ba045c-repo` — `fetch-thermal-video.yml`).
- Шаблон «мост»: файл-заявка в ветке (`assets/requests/*.json`) → push → Actions с интернетом скачивает/обрабатывает → публикует в ветку-канал → агент забирает pull-скриптом.
- Для радио планируется `radio-fetch.yml` (Яндекс.Диск → `radio-inbox` с ffprobe/loudnorm) и ветка `radio-data` (`tracks.json`, `playlists.json`; ключ — SHA-256, как в `music_index.json`).
- В локальном чате интернет есть, поэтому Actions — это версионируемый транспорт и триггер, а не обход блокировок.

## 4. Ссылки и сдача

- Тег на сдаваемый коммит: `git tag -f delivery_radio_YYYY_MM_DD <sha> && git push -f origin refs/tags/delivery_radio_YYYY_MM_DD`.
- Ссылки на файлы — `blob/<tag>/<путь>` (посмотреть) и `raw/<tag>/<путь>` (скачать). Имя ветки со слэшем (`arena/…`, `radio/…`) в raw-ссылках ломается — не использовать (см. `LINKS_POLICY.md`).
- Файлы в `.gitignore` (`*.mp4`) не сдавать: либо исключение в `.gitignore` ветки, либо ветка-канал.

## 5. Гигиена

- Лимит GitHub — 100 МБ на файл и рекомендация <1 ГБ на репозиторий; репозиторий уже 5+ ГБ, поэтому медиа — точечно.
- Не трогать ветки-каналы и `arena/*` других чатов: их перезапись (force-push) — чужая зона.
- Не пушить в `main`; не переписывать историю `main`; не удалять теги доставки без предупреждения.
- Секреты, пароли, Telegram-сессии, OAuth-токены — не коммитить никогда (репозиторий публичный).
