# Радио «В ОКОПЕ» — рабочая папка в репозитории

Потоковое военное радио «В ОКОПЕ»: 24/7 эфир, песни о войне и победе, реклама магазина, брендинг, YouTube-канал [@V-okope](https://www.youtube.com/@V-okope).

Здесь живут **готовые продукты радио**, которые должны быть в `main` (код, звук, документы). Всё, что связано с чужими чатами команды (каталог магазина, видеостудия, посты) — в их ветках, см. карту ниже.

## Что в папке

| Путь | Что |
|---|---|
| `jingle/` | **5 готовых джинглов радио** (3,50–4,40 с, −13 LUFS): `vokope_jingle_1_udar`, `_2_pozyvnye` (голос через рацию), `_3_drayv`, `_4_marsh`, `_5_podlozhka`. Каждый — mp3 320 кбит/с + WAV 48 кГц/16 бит (мастер для эфирного сервера). Плюс `README.md`, `publish.txt` (куда какой ставить), `build_jingles.py` (пересборка), `jingles.json`/`wav_report.json` (замеры), `vo/` (4 голосовых сырья) |
| `ads/ТЕКСТЫ_РЕКЛАМЫ.md` | Тексты рекламных отбивок 5/15/30/60 с и строки для титров |
| `GITHUB_WORKFLOW.md` | Регламент: как чат «Радио» работает через GitHub |

## Как поставить джингл в эфир

1. Взять `.wav`-мастер из `jingle/` (не mp3) — эфирный сервер принимает WAV 48 кГц/16 бит.
2. Положить в `brand/jingles/` эфирного контура.
3. Указать в `config.json` → `jingle.audio_file`; частота вставки — `jingle.every_songs` (сейчас каждые 3 песни).
4. По паспорту `publish.txt`: №1 — основная отбивка перед рубрикой, №2 — «вы слушаете радио», №3 — динамичные анонсы, №4 — серьёзная/парадная тема, №5 — под начитку ведущего.

## Правила

1. Музыка: **никакой генеративной/процедурной музыки** (`MUSIC_POLICY.md`); джинглы собраны только из реальных треков `music_downloaded/` и CC0-SFX — так и продолжать.
2. Секреты (пароли, Telegram-сессии, `client.json`/`token.json` YouTube, ключи) в git **не попадают**. Репозиторий публичный.
3. Большие медиа не коммитить: `.mp4` в `.gitignore`; видео — частями или через ветки-каналы.
4. Ссылки на файлы — по тегу (`delivery_…`) или SHA, не по имени ветки со слэшем (`LINKS_POLICY.md`).
5. «Пост-Россия» — только по явному решению владельца (права Suno + текст).
6. Изменения — через ветку `radio/<тема>` и PR, не напрямую в `main` (см. `GITHUB_WORKFLOW.md`).
