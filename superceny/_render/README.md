# _render — пайплайн «СУПЕРЦЕНЫ»

Рендер 81 PNG (20 позиций × 4 карточки + hero) из `superceny/03_HTML/` в
`superceny/05_ГОТОВОЕ/`, галерея и чек-лист. База — пайплайн `banners/_render`
(Chrome CDP, детектор наложений/переполнений), адаптирован под папочную структуру.
Состав — по брифу §9 (уточнение заказчика 11.11.2026): 20 позиций прайса.

## Быстрый старт

```powershell
# полный прогон: preflight → рендер (батчами, с очисткой старых PNG) → галерея → чек-лист
powershell -NoProfile -ExecutionPolicy Bypass -File superceny\_render\run_all.ps1

# проверить комплектность HTML до рендера
& $py superceny\_render\preflight.py

# только новые/изменившиеся HTML (докатка), батч 40
& $py superceny\_render\render_cards.py --all --only-new --batch-size 40

# одна позиция / одна папка / одна карточка
& $py superceny\_render\render_cards.py --folder 01_Муха
& $py superceny\_render\render_cards.py "superceny\03_HTML\01_Муха-К-8\01_СУПЕРЦЕНА.html"
& $py superceny\_render\render_cards.py --only 00,01     # hero + суперцены

# доп. 2× в <folder>/@2x/ (не входит в обязательные 81)
& $py superceny\_render\render_cards.py --all --2x
```

Python с Pillow: `C:\Users\TitanPC\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`

## Скрипты

| Файл | Что делает |
|---|---|
| `superlib.py` | пути, раскладка HTML→PNG (папки позиций, hero), meta из `01_ДАННЫЕ/positions.json`, константы состава (20 позиций / 80 карточек / 81 PNG) |
| `preflight.py` | проверка «80+1 HTML готовы»: папки, карточки 01–04, hero |
| `render_cards.py` | CDP-рендер 1080×1350 батчами: точные размеры, битые фото, переполнение документа, текст за кадром, наложения текста; `--prune` убирает PNG старой версии; JSON-отчёт |
| `gallery.py` | `05_ГОТОВОЕ/gallery/index.html` — hero + 20 позиций × 4 карточки, офлайн |
| `check_files.py` | приёмка: 81 PNG, структура папок, размеры/веса/время рендера → `ЧЕК_ЛИСТ_ФАЙЛОВ.md` |
| `run_all.ps1` | последовательный прогон (батч 40, с `--prune`) |

## Раскладка

`03_HTML/<NN_Название>/01_СУПЕРЦЕНА.html` → `05_ГОТОВОЕ/<NN_Название>/01_СУПЕРЦЕНА.png`
(и так же 02 ХАРАКТЕРИСТИКИ, 03 ПРИМЕНЕНИЕ, 04 СУПЕР-ПРЕДЛОЖЕНИЕ).
`03_HTML/00_СУПЕРЦЕНЫ.html` → `05_ГОТОВОЕ/00_СУПЕРЦЕНЫ.png` (hero).
Имя PNG всегда каноническое по номеру карточки (`00_СУПЕРЦЕНЫ` … `04_СУПЕР-ПРЕДЛОЖЕНИЕ`),
даже если HTML назван чуть иначе. Папки — из `positions.json` (01–20, как у заказчика).

## Детектор

FAIL: битые `<img>`, переполнение документа (контент больше 1080×1350 — была бы обрезка),
текст за границей кадра, ошибки шрифтов, неверный размер/вес PNG.
WARN: `overflow:hidden` с обрезанным содержимым (обычно намеренный кроп фото),
наложения текстовых блоков (>35% площади), шрифты не в состоянии `loaded`.

Отчёт: `_render/_qa/render_report.json` (по каждому файлу, с `rendered_at`).
Если карточка сломана — сообщение Lead/designer-a с путём HTML и PNG; **HTML не правим**.

## Особенности больших прогонов

- Рендер идёт батчами (`--batch-size`, по умолчанию 40): каждые N карточек Chrome
  перезапускается — стабильность на длинном прогоне, прогресс печатается.
- `--only-new` докатывает только изменившиеся HTML (mtime HTML > mtime PNG).
- `--prune` удаляет из `05_ГОТОВОЕ` PNG/папки, которых нет в текущем составе
  (нужно при смене версии: 43 позиции → 20 позиций).
- Позиции 01 «Муха К-8» и 08 «Изделие 135 Багажный бокс» — без данных каталога,
  карточки с пометкой «характеристики — по запросу»; это норма, не дефект.
