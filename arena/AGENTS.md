# Общий штаб «В ОКОПЕ» — правила для всех агентов

Этот репозиторий — общая рабочая площадка команды «В ОКОПЕ». Здесь общаются **локальный чат-координатор «Радио»** (id `radio`) и **облачные агенты Arena** (каждая сессия Arena = ветка `arena/<id>-repo` + PR). Человек-владелец — постановщик и арбитр.

## 1. Четыре канала

| Канал | Путь | Что писать |
|---|---|---|
| Доска задач | `arena/tasks/T-XXXX.md` | задачи и их статусы (todo → doing → done/blocked) |
| Почта | `arena/mail/out/NNNN-radio.md`, `arena/mail/in/NNNN-arena.md` | адресные письма «координатор ↔ конкретная сессия» |
| Говорилка | `arena/chat/<время>-<кто>.md` | короткие сообщения «всем» и «между собой» |
| Реестр сессий | `arena/sessions/<ветка>.md` | кто запускался, над чем работал, что осталось |

## 2. Цикл работы (любая Arena-сессия)

1. **Прочитай** свежий `main`: `AGENTS.md` → `arena/AGENTS.md` → доску `arena/tasks/` → непрочитанную почту `arena/mail/` → говорилку `arena/chat/`.
2. **Возьми задачу.** Если человек в промпте указал конкретную — её. Иначе — самую приоритетную со статусом `todo` (priority: high → normal → low). Перед работой отметь в файле задачи: `status: doing`, `owner: arena:<ветка или id>`, `updated: <дата>`.
3. **Сделай** работу в своей ветке `arena/<id>-repo`, как обычно.
4. **Положи результат — обязательно, даже если не получилось:**
   - в файл задачи: `status: done` (или `blocked` + причина) и раздел «Результат» со ссылками;
   - письмо в `arena/mail/in/<номер>-arena.md` (ответ на задание координатора);
   - короткое сообщение в говорилку: `arena/chat/<YYYYMMDD-HHMMSS>-arena-<4hex>.md` — 1–3 строки: «взял T-0002», «готово, PR #N», «вопрос: …»;
   - при старте — запись в `arena/sessions/<ветка>.md`: тема, время, что сделано/осталось.
5. **Открой PR** в `main` (одна сессия = один PR). Не пушь в `main` напрямую и не мержи сам.

## 3. Как общаться между собой

- **Координатор → сессия:** письмо в `arena/mail/out/NNNN-radio.md` (в нём `from: radio`, `to: arena` или `to: arena:<ветка>`), плюс запись на доске при необходимости.
- **Сессия → координатор:** письмо `arena/mail/in/NNNN-arena.md` + сообщение в говорилку.
- **Сессия ↔ сессия:** сообщения в `arena/chat/` (`to: all` или `to: arena:<ветка>`); передача подзадачи — новый файл `arena/tasks/T-XXXX.md` со ссылкой на родительскую задачу в теле. Не редактируй чужие файлы задач, кроме назначенных тебе; не трогай чужие ветки.
- **Асинхронность:** сессии не видят друг друга в реальном времени. «Разбудить» следующую сессию может только человек — поэтому всё важное должно быть записано в файлы, а не сказано в чате Arena.

## 4. Форматы

**Задача** `arena/tasks/T-0001.md`:
```markdown
---
id: T-0001
title: короткое название
status: todo          # todo | doing | done | blocked
owner: -              # radio | arena:<ветка>
priority: normal      # high | normal | low
parent: -             # T-XXXX, если это подзадача
created: 2026-11-03T19:30+03:00
updated: 2026-11-03T19:30+03:00
---
## Что сделать
…
## Готово, когда
…
## Результат
(заполняет исполнитель: ссылки на ветку/PR/файлы, что осталось)
```

**Письмо** — front matter `from/to/id/date/topic/re` (см. `arena/README.md`), тело — свободный текст.

**Сообщение в говорилку** `arena/chat/20261103-193000-arena-ab12.md`:
```markdown
---
from: arena            # radio | arena
to: all                # all | arena:<ветка> | radio
date: 2026-11-03T19:30:00+03:00
---
Текст 1–3 строки.
```

**Сессия** `arena/sessions/arena-<id>-repo.md`:
```markdown
---
branch: arena/<id>-repo
topic: …
started: 2026-11-03T19:00+03:00
status: working        # working | done | blocked
---
Что сделано, что осталось, какие файлы/PR.
```

## 5. Ограничения (жёсткие)

1. Репозиторий **публичный**: никаких секретов, паролей, токенов, Telegram-сессий, внутренних адресов — ни в задачах, ни в письмах, ни в говорилке.
2. Не коммитить большие медиа (`*.mp4`, архивы, музыка) — только ссылки/теги или отдельные ветки-каналы.
3. Не пушить в `main`; не редактировать чужие ветки; не удалять чужие файлы задач/писем/сообщений.
4. Не мержить PR самому: после merge/close Arena-сессия теряет право пуша (по документации Arena).
5. Не создавать по несколько PR на одну сессию — одна сессия = один PR.
6. Не трогать ветки-каналы других чатов (`catalog-data`, `frontts-data`, `assets-inbox*`) — их перезапись чужая зона.
7. Если задача требует внешней сети, а у песочницы Arena её нет — оформи заявку-файл по образцу Actions-моста (`assets/requests/*.json`) или попроси координатора; не изобретай обходы.

## 6. Роли

- `radio` (локальный чат-координатор): ставит задачи, отвечает на письма, разбирает PR, обновляет доску, ведёт проект.
- Arena-сессии: исполнители-сабагенты. Могут брать задачи сами с доски и оставлять подзадачи другим сессиям.
- Человек-владелец: запускает сессии, даёт финальные «ок», мержит PR.
