# Мост «чат «Радио» ↔ Arena»

Обмен сообщениями и задачами между локальным чатом «Радио» (DSH на рабочем ПК) и облачными агентами Arena — через этот GitHub-репозиторий. У Arena нет публичного API для внешних программ, зато есть официальная GitHub-интеграция: сессия клонирует репозиторий, работает в ветке и открывает PR. Это и есть канал.

## Почему это безопасно для аккаунта

- Никакой автоматизации arena.ai: не используются куки, не дёргаются внутренние API, не эмулируется браузер.
- Сессию Arena открывает и ведёт человек — как обычно.
- Вся программа-посредник работает только с GitHub (`gh`/`git`), в пределах обычных прав токена.
- Сообщения — маленькие текстовые файлы, без секретов и больших медиа (репозиторий публичный).

## Как устроено

```
локальный чат «Радио»  ──пишет──▶  arena/mail/out/NNNN-radio.md   (в main)
                                          │
                                          ▼  человек открывает Arena-сессию
                                   агент Arena читает задание
                                          │
                                          ▼
локальный чат читает  ◀──пушит──  arena/mail/in/NNNN-arena.md      (в ветке Arena / PR)
```

- `arena/mail/out/` — исходящие от чата «Радио». Имя: `NNNN-radio.md`, NNNN — номер по порядку.
- `arena/mail/in/` — ответы/результаты от Arena. Имя: `NNNN-arena.md` (тот же номер, что у задания).
- `arena/PROMPT.md` — готовая вставка для Arena-сессии (человек копирует в чат Arena).
- Номера увеличиваются; «последнее сообщение» = максимальный NNNN. Ответ на задание NNNN — файл `in/NNNN-arena.md`.

## Формат письма

```markdown
---
from: radio          # или arena
to: arena            # или radio
id: 0001
date: 2026-11-03T19:00+03:00
topic: короткая тема
re: 0000             # для ответа — номер задания; у нового задания не нужно
---
Текст задания или ответа. Можно списком, можно с ссылками на файлы репозитория.
```

## Правила

1. Не удалять и не переписывать старые письма — только добавлять новые файлы.
2. Секреты, пароли, токены, Telegram-сессии, номера/адреса — в письма не писать (репозиторий публичный).
3. Большие файлы (видео, музыка, архивы) в письма не вкладывать — только ссылки на ветки/теги или отдельный PR.
4. Arena сдаёт результат **веткой + PR** (одна сессия = один PR), файлы ответа кладёт в `arena/mail/in/`.
5. Локальный чат читает новые `in/`-файлы сначала в `main`, затем в открытых ветках `arena/*` (поэтому ответ виден даже до merge).
6. Merge PR — после того как сессия Arena закончила (после merge/close Arena больше не может пушить).

## Быстрый старт

1. Локальный чат пишет задание: `github.ps1 mail-send "текст задания"` (создаёт `out/NNNN-radio.md`).
2. Владелец: Arena → новая сессия с репозиторием → вставить содержимое `arena/PROMPT.md` → отправить.
3. Arena выполняет, пушит ветку/PR с `arena/mail/in/NNNN-arena.md` (и результатами).
4. Локальный чат: `github.ps1 mail` — показывает новые ответы; дальше — разбор, перенос в проект, следующий вопрос.
