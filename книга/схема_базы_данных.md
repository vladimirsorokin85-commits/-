# Схема базы данных канона

`вселенная.db` — SQLite 3, кодировка UTF-8, `PRAGMA user_version = 1`. База всегда пересобирается целиком из `данные/canon.json` скриптом `инструменты/build_db.py`, поэтому единственный источник правды — JSON.

## Связи

```
sections ──< facts >── entities
    │                     │
    └──< open_questions   └──< parameters
    └──< violation_categories
    └──< sanctions
    └──< glossary >── entities
```

Все внешние ключи объявлены с `ON DELETE SET NULL`. При сборке включается `PRAGMA foreign_keys = ON`, так что битые ссылки не пройдут.

## Таблицы

### `meta`
Пары «ключ — значение»: `schema_version`, `title`, `volume`, `version`, `status`, `author`, `genres`, `language`, `created`, `updated`, `source_document`, `description`, `built_at` (время сборки, UTC).

### `sections` — разделы канона
| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | TEXT PK | Номер раздела как идентификатор: `3`, `3.1`, `14.2` |
| `number` | TEXT | Номер в документе |
| `title` | TEXT | Заголовок |
| `parent_id` | TEXT FK → `sections.id` | Родительский раздел, если это подраздел |
| `summary` | TEXT | Краткое содержание |
| `sort_order` | INTEGER | Порядок в документе |

### `entities` — сущности мира
| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | TEXT PK | Латинский идентификатор: `security_service`, `police` |
| `type` | TEXT | `state`, `person`, `agency`, `institution`, `system`, `technology`, `infrastructure`, `facility`, `service`, `social_group` |
| `name` | TEXT | Название |
| `aliases` | TEXT | Прозвища и синонимы через запятую: `СБ, Коршуны` |
| `summary` | TEXT | Описание в одно-два предложения |
| `canon` | TEXT | Статус достоверности |
| `section_id` | TEXT FK | Основной раздел |

### `facts` — утверждения канона
| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | TEXT PK | `F-001`…`F-183`, нумерация непрерывная |
| `section_id` | TEXT FK | Раздел-источник |
| `entity_id` | TEXT FK | О ком/о чём утверждение, может быть пустым |
| `kind` | TEXT | Тип утверждения, см. ниже |
| `canon` | TEXT | Статус достоверности |
| `statement` | TEXT | Формулировка, максимально близкая к документу |
| `tags` | TEXT | Метки через запятую для поиска |
| `sort_order` | INTEGER | Порядок внутри документа |

Типы утверждений (`kind`): `rule` (правило), `procedure` (процедура), `right` (право), `restriction` (ограничение), `sanction` (мера наказания), `norm` (норматив), `principle` (принцип), `description` (описание), `example` (пример), `statistic` (числовой факт), `exception` (исключение), `rumor` (слух).

### `parameters` — числовые параметры
| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | TEXT PK | `P-001`…`P-015` |
| `name` | TEXT | Название параметра |
| `value` | TEXT | Как в документе: «не более 2 минут», «1–2 балла» |
| `value_num` | REAL | Число для расчётов и сравнений, если применимо |
| `unit` | TEXT | `мин`, `балл`, `%`, `год`, `категория` |
| `comparison` | TEXT | `=`, `<=`, `~`, `range` |
| `entity_id`, `section_id` | TEXT FK | Привязка |
| `note` | TEXT | Уточнение |

`value` хранится для цитирования, `value_num` — для вычислений. Для диапазонов в `value_num` лежит верхняя граница, точный диапазон — в `value`. В отдельных случаях `value` нормализовано («1 год» вместо «год без новых нарушений»); исходная формулировка документа приведена в `note`.

### `violation_categories` — категории правонарушений
`id`, `name`, `deferred` (0/1 — возможно ли отложенное наказание), `court` (куда попадает дело), `notes`, `section_id`, `sort_order`. Четыре записи: лёгкие, средние, тяжкие, особо тяжкие.

### `sanctions` — виды наказаний
`id`, `name`, `applies_to`, `notes`, `section_id`, `sort_order`. Семь записей: штраф, работы, лишение свободы, испытательный срок, снижение лимита, принудительный труд, дисциплинарные меры.

### `glossary` — термины мира
`term` (PK), `definition`, `section_id`, `entity_id`. Внутримировые понятия и жаргон: «баллы», «погашение», «Коршуны», «Поля», «Шахты», «лептоп».

### `open_questions` — нерешённые вопросы
| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | TEXT PK | `Q-01`… |
| `question` | TEXT | Формулировка |
| `section_id` | TEXT FK | К какому разделу относится |
| `status` | TEXT | `open`, `resolved`, `deferred`, `wontfix` |
| `origin` | TEXT | `document` — из раздела 20, `editorial` — найден при разборе |

### `sources` и `versions`
`sources` — откуда взят канон (документ, версия, путь, статус). `versions` — история версий: `version` (PK), `date`, `status`, `changes`, `document`.

## Представления

| Представление | Что показывает |
| --- | --- |
| `v_facts_full` | Утверждения с номером и названием раздела, именем и типом сущности |
| `v_entities_full` | Сущности с названием основного раздела |
| `v_parameters_full` | Параметры с разделом и сущностью |
| `v_open_questions` | Открытые вопросы с разделом |

## Проверки при сборке

`build_db.py` до записи в базу проверяет:

- уникальность всех `id` и терминов;
- существование разделов-родителей и ссылок `section` / `entity` у всех записей;
- допустимые значения `canon` и `status`;
- формат и непрерывность нумерации `F-xxx`;
- что `value_num` — число;
- что у каждого раздела есть хотя бы одно утверждение или открытый вопрос (иначе предупреждение).

## Правила расширения

- Новые сущности — латинский `id` в `snake_case`, русское `name`, при необходимости `aliases`.
- Новое утверждение — следующий свободный `F-xxx`, обязательные `section`, `kind`, `canon`, `statement`.
- Изменение канона — не удаление, а смена статуса старой записи и добавление новой; запись в `versions`.
- Числа из текста всегда дублируются в `parameters`, чтобы их можно было сверять программно.
- После любых правок: `python3 книга/инструменты/build_db.py`.
