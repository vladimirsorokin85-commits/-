| **Б2** | Запрещённая формулировка / нейрослоп / военная риторика | «100% защита», «дрон не пролети́т», «передовая» | не сдано |
| **Б3** | Визуальный брак: переполнение, обрезка, битое/размытое фото, подмена шрифта, кегль < 13 px, контраст < 4.5:1, безопасные поля < 24 px, градиент/тень/неон | текст вылезает за плашку | не сдано |

| **Б5** | Утечка цены (₽, руб., «от N») в постер или файл пакета | «К-8М — 350 000 ₽» | не сдано, секрет |

Каждый дефект в отчёте = **код + путь к файлу + цитата + что исправить + кто (дизайнер/рендерер/factchecker/Lead)**.
Без пути и цитаты замечание не принимается.

## 4. Блок A — Факты и цифры (главный)

1. `check_claims.py` извлекает текст каждого постера (html.parser: text nodes + SVG `<text>` +
   `alt`/`aria-label`; `<style>`,`<script>` исключены).
2. Все числовые токены с единицами (МГц, ГГц, м, км, Вт, кВт, кг, г, А·ч, ч, мин, мес, %,
   ₽/руб., км/ч, °C, м², «каналов/генераторов/передатчиков/моноблоков/позиций/семейств/
   моделей/шагов/типов») сверяются с `numbers` + текстом `claims.json`:
   - точное значение/единица → OK;
   - значение внутри подтверждённого диапазона той же единицы (1000 м ⊂ 1000–5000 м) → OK
     при совпадении границ или вхождении;
   - нет совпадения → **Б1**, вывести значение, единицу, соседние 60 знаков, файл.
3. Отдельно: цены. Любые `₽`, `руб.`, `цена`, `стоимость`, `прайс`, «от N ₽» в постерах —
   **Б5** (внутренняя цена поставщика не публикуется). Значения цен в отчёт не копирую.
   Рыночная цифра «12 млрд ₽» допустима только если она есть в claims.json.
4. Даты/годы, номера законов, решения ГКРЧ, телефон — тоже сверяются с claims.json;
   если их там нет — **З** (виз. пометка «вне факт-базы»).
5. Выборочная сверка claims → первоисточник: для claim с `source` = локальный файл
   проверяю, что числа `numbers` встречаются в этом файле; расхождение = **Б1** (факт-база врёт).
6. Покрытие: сколько цифр в постере, сколько из них привязано к claim (через `poster_ids`).
   Постер без единой опоры на claims = **Б2** (текст «из воздуха»).
7. Ручная сверка: по каждому постеру читаю claims.json глазами и выписываю таблицу
   «цифра в постере → claim_id → источник». Совпадение подтверждаю цитатой.

## 6. Блок C — Визуал HTML (до рендера и после)

`check_layout.py`: копия постера в `03_QA\_tmp\` + внедрённый замерщик, Chrome headless
`--dump-dom`; скрипт кладёт JSON с замерами в DOM. Проверяю:
- переполнение: у элементов с фикс. высотой/плашками `scrollHeight > clientHeight + 1`,
  текст за пределами `1080×1350` (getBoundingClientRect), горизонтальный скролл;
- перекрытие: пересечение bbox текстовых блоков (эвристика, ручная доводка);
- кегли: все `font-size < 13px` → **Б3** (кроме служебной линейки ≤11 px — **З**);
- шрифты: `getComputedStyle().fontFamily` основных блоков — только Sofia Sans Cond /
  Oswald / Tektur / Segoe UI; ни одного `Arial/Helvetica/Times` в вычисленной цепочке;
  `document.fonts.check('...')` для трёх шрифтов = true (локальные @font-face подхватились);
- фото: `img.naturalWidth > 0` (не битые), доля апскейла (`naturalWidth < отображаемая
  ширина` → размытие = **Б3**), `alt` заполнен;
- контраст: считаю WCAG для пар (цвет элемента / фактический фон) по порогам 4.5:1
  основного текста, 3:1 крупного; градиентный фон = **Б3** (запрещён);
- безопасные поля: bbox контента ≥ 24 px от края холста (кроме служебной линейки);
- один акцент: уникальных «акцентных» цветов (насыщенность > 60%) ≤ 2 (акцент + сигнальный);
- запрещено в CSS: `linear-gradient`, `radial-gradient`, `box-shadow`, `text-shadow`,
  `filter: blur`, `backdrop-filter`, `text-shadow`, неон (`0 0 Npx`), внешние шрифты/картинки.

## 7. Блок D — Визуал PNG (финальный)

1. `check_png.py` (Pillow): размеры 1080×1350 / 2160×2700 / 1920×1080 / 1080×1920, mode =
   RGB (без альфы), sRGB-профиль или его отсутствие допустимо, вес разумный,
   файл не однобуквенный (не пустой/не однотонный), нет полос-артефактов.
2. Ручной `read_image` **каждого** PNG P01–P10 (и wide/story, если есть): переполнения,
   обрезка текста и фото, читаемость подписей, контраст, «поплывшие»/подменённые шрифты,
   соответствие фото модели (сверяю подпись с именем модели и каталогом), битые/размытые
   фото, безопасные поля, один акцент, отсутствие градиентов/теней/неона, ровные линии.
3. Сверяю, что PNG соответствует HTML-версии (по тексту и композиции).

  3) «Технические характеристики — по паспорту изделия; значения дальности зависят от

## 10. Блок G — Читаемость на телефоне

- Заголовок читается на превью 390 px (уменьшаю изображение до ширины 390 и смотрю
  через `read_image`): главный вывод различим, не мельче ~20 px в исходнике для headers.
- Кегль подписей ≥ 13 px на холсте 1080; в 2× эквивалент ≥ 26 px.
- Контраст ≥ 4.5:1 для основного текста, ≥ 3:1 для крупного (>24 px bold / >18.66 px).
- Никаких элементов ближе 24 px к краю, кроме служебной линейки.
- Сторис: безопасные зоны под UI Telegram (сверху ~250 px, снизу ~250 px для CTA) — **З/Б3**
  если CTA перекрывается интерфейсом (проверить по макету).

## 12. Таблица отчёта (форма)

```
| Постер | Факты | Антислоп | Визуал | CTA | Дисклеймер | Вердикт |
| P01 | ✅/⚠/❌ | ... | ... | ... | n/a | сдано/замечания/не сдано |
```

Вердикт пакета: **сдано** (0 блокеров, 0 З без принятия Lead) / **сдано с замечаниями**
(0 блокеров, есть З, перечислены) / **не сдано** (≥1 блокер). В «не сдано» — список
исправлений по адресатам и повторная проверка.

## 13. Доказательства проверки (обязательно в отчёте)

- Пути ко всем проверенным файлам + дата/время прогона.
- Для каждого «✅» — чем подтверждено: результат линтера (строка), цитата, замер,
  просмотренный PNG (имя), число страниц PDF.
- Скриншоты/превью проблем — в `03_QA\_evidence\` (только мои файлы).
- Никаких «проверено визуально» без указания, что именно смотрел.

## 14. Красные линии

1. Ни одной цифры «на глаз»: всё через claims.json и первоисточник.
2. Цены и внутренние прайсы не публикую и не цитирую значениями — только факт утечки.
3. Замечание без пути/цитаты — не замечание.
4. Спорный факт не «исправляю» — эскалирую Lead (и factchecker), фиксирую в отчёте.
5. Макеты не трогаю даже ради «быстрого фикса».
